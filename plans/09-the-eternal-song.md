# 无限合唱 The Eternal Song

全网同步播放同一首永远在变长的歌。每位访客只能在歌曲结尾的下一个空位放一个 0.5 秒的音，永久编号、不可修改。你可以把时间轴拖回开头，听这条由百万人一格一格写成的旋律如何自发涌现。这是一个 append-only 的集体创作纪念碑。

**核心体验与情绪钩子**　你贡献的这 0.5 秒会拿到一个永久编号、永不可改，成为一首百万人共写之歌的确切一格。留名于一件永恒作品的庄严感，叠加"集体无意识竟然长出了旋律"的涌现惊喜，构成既低门槛又上瘾的钩子。

**详细玩法与规则**　从一套精选音色 / 节奏调色板里点选一个音（不开麦，从源头保证不刺耳），放进歌曲末尾的下一个空位，立刻获得永久编号。任何人都能拖动时间轴从头听整条时间线，看旋律怎样一段段成形。

**分享卡设计**　"第 1,204,332 个音是我的，在 6 分 03 秒处"——分享卡带上你那一小段的可播放波形和定位链接，点开直接跳到并高亮你的音，精确坐标本身就是可炫耀的无剧透素材。

**留存与回访**　歌一直在长，你会回来听"我之后大家又加了什么"。里程碑（第 100 万个音）做成事件，你的音附近逐渐成形的"乐句"带来段落归属感，都是持续回访的动力。

**技术实现**　三件核心事。其一 append-only 存储：每个音是一条永不重写的记录（编号 + 音色 id + 时间戳），天然适合日志型存储 / 对象存储分片。其二时间轴同步：客户端不流式拉整曲，而是按需分段加载音符元数据，用 Web Audio API 在本地拼接合成，音色样本走 CDN 缓存——服务端只发元数据，带宽极省。其三写入是关键路径：追加新音需要全局原子递增编号，高并发下用 Redis INCR 或单写入者队列把写入串行化，杜绝编号冲突与空位争抢。只有"歌尾正被填充"的活跃区需要 WebSocket 轻推最新音与当前长度，播放历史完全不需实时。整体读多写少、纯追加，极易水平扩展。

**防滥用 / 反作弊**　调色板限定输入 → 内容天然安全，无需审核开麦语音。主要防脚本刷音抢占编号（按人限速、节流）、以及有人短时间刷屏破坏旋律（时间窗内限量 + 冷却）。

**冷启动与宣发**　开头几百个音要"种"得好听，由团队预置一段主动机定调；"给一首永恒的歌加一个音"门槛极低、天然易传播；可视化时间轴与延时增长过程很适合短视频观赏。

**盈利模式**　工具 / 收藏向变现最顺：付费解锁高级音色包（IAP 最自然）、你的音的永久铭牌、里程碑音位竞拍，以及用激励视频兑换稀有音色（IAA）。

**MVP 范围与开发量**　调色板 UI + Web Audio 拼接播放 + append 写入 + 编号系统 + 时间轴拖动 + 分享定位，约 3–4 周。音频拼接与时间轴同步是主要工作量。

**主要风险与化解**　最大风险是百万音后旋律沦为噪音、加载变重：用算法为每个新音约束到当前音阶 / 和声上，保证越长越不难听；用分段加载 + 把历史段落 CDN 静态化，配合分片归档，控制 append 存储无限膨胀与首屏成本。
